## 配对离线验证

同一 35 任务、350 条留出轨迹，每轨迹四个时间分区中点，共 1,400 个真实三相机观测；
共 50,884 个有效动作时间步。每任务 3 条 VQA，共 105 条、2,723 个答案 token。
两轮 frame selection、VQA 内容、动作 mask、归一化统计和评测配置已逐项核对一致。

| 指标（越低越好） | 30k | 40k |
| --- | ---: | ---: |
| 任务等权 normalized L1 | 0.042498 | 0.040533 |
| 有效动作步加权 normalized L1 | 0.044345 | 0.042399 |
| VQA 答案 token 交叉熵 | 0.107893 | 0.147221 |
| push_T 单任务离线 normalized L1 | 0.064229 | 0.059966 |

40k 的任务平均动作误差降低 4.63%，30/35 个任务改善；VQA 在这个固定抽样上的答案交叉熵上升。
这不足以推断整体 VQA 能力变化，更不能用离线误差直接推断机器人成功率。
标注仍为未经人工逐条验收的伪标签，评测是 validation 而非独立 test；未做 VQA 自由生成准确率测试。

动作误差改善最大的任务包括拼 RoboDojo、投硬币、扫积木、插充电器和叠衣服。
退化的 5 项为分类物体、装笔筒、投瓶子、整理桌面和装箱。逐任务数值见 CSV。

## 本机部署与闭环

两份权重均通过 native 严格重载，以及 RoboDojo vendored StarVLA 服务端严格重载。
每份权重用 35 个任务各一个真实验证观测，检查完整 50×14 有限动作、runtime contract、
ARX X5 动作顺序、动作块推进及同文本不同 subtask_id 的立即重新推理。

- 30k：`ws://127.0.0.1:6000`，后台 StarVLA 端口 54501。
- 40k：`ws://127.0.0.1:6001`，后台 StarVLA 端口 56667。
- [30k 服务验证](../../eval_result/vlact_30000_a800_20260926/server_check.json)
- [40k 服务验证](../../eval_result/vlact_40000_a800_20260926/server_check.json)

`push_T_state_v1` 仅根据当前真值对齐和夹爪状态切换推动/释放/回位；模型不接收真值坐标。
两轮使用官方 `push_T` 布局 seed=0 / layout_id=0、单环境、horizon=16、原始 600 步上限。
这只是单布局 state-oracle smoke，不是完整任务成功率或自主规划成绩。

| checkpoint | 有效回合 | 成功 | 得分 /100 | 控制步 | unstable |
| --- | ---: | ---: | ---: | ---: | ---: |
| 30k | 1 | 0 | 0 | 600 | 0 |
| 40k | 1 | 0 | 0 | 600 | 0 |

两轮三路相机视频均为 601 帧、640×480、25 FPS，RGB 画面和运动已验证。
两轮均未达到 oracle 对齐条件，整个回合停留在 push 阶段。30k 主相机画面中机械臂接触 T 块后基本停滞；40k 的动作有所不同，但同样未完成任务。两轮 unstable=0，未放弃布局。释放/回位与恢复阶段的切换通过单元测试，但这两次失败回合未实际触发这些阶段，仍需后续成功回合验证。
