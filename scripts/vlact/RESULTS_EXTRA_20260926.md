## 实际动作与阶段进度

| 任务 | 30k 观察 | 40k 观察 |
| --- | --- | --- |
| 插充电器 | 第 45 步进入交接，第 112 步进入插入；未达到插入条件，之后重新抓取；共 6 次阶段切换 | 第 47 步进入交接，第 114 步进入插入；插头落回插座旁桌面；共 3 次阶段切换 |
| 插试管 | 完整插入数量始终为 0；试管被搬到架子上，但横放，未竖直插入 | 完整插入数量始终为 0；后半段支架被带离初始位置 |
| 倒球 | 第 52 步进入倒球，第 156 步回到抓杯；杯子侧翻、球散落桌面；入瓶球数峰值 1、末次 0 | 第 46 步进入倒球；杯子被带到花瓶左侧后停留；入瓶球数峰值 4、末次 0，未进入放杯/回位阶段 |

球数和插入数量来自控制前的当前状态判定；“末次”指最后一条 oracle 观测。
短暂入瓶不代表球被稳定保留，更不代表任务成功；正式成功与得分以控制结束后的官方 `_result.json` 为准。
倒球任务没有按球数计算的官方部分得分。视频验证了以上失败现象。

此前离线验证中，这三个任务的 normalized L1 都在 40k 更低：

| 任务 | 30k L1 | 40k L1 |
| --- | ---: | ---: |
| 插充电器 | 0.012684 | 0.008250 |
| 插试管 | 0.011785 | 0.008930 |
| 倒球入花瓶 | 0.062055 | 0.060000 |

在这三个单布局闭环回合中，尚未看到正式成功率的改善，不能仅凭离线误差选择更优的在线 checkpoint。
40k 倒球的过程峰值较高，但最终没有保持入瓶状态，也不足以说明总体更好。

## 评测设置与边界

- checkpoint 固定为 `qwen36_full_8h100_20260924/full_train/checkpoints/steps_30000_pytorch_model.pt`
  和 `steps_40000_pytorch_model.pt`，服务端分别为本机 6000、6001。
- 沿用已验证的训练统计、RGB 三相机、224×224、`include_state=false`、50×14 绝对关节动作、执行 horizon=16。
- 每个任务使用 `<task>_state_v1` 状态提示。模型输入是当前 RGB 与任务/原子指令文字；
  特权物体位姿及夹爪状态仅用于选择阶段，不直接输入模型。不改变官方 reward、布局或步数上限。
- 新阶段要求连续三个不同控制观测支持；物体掉落、插入条件丢失后可回退。没有读取未来演示时间戳或动作。
  插充电器的交接使用 X5 抓取点距离与夹爪开度近似判断，详见 README 和每轮 `oracle_config.json`。
- 本轮不是自主规划测试。结果同时受到策略执行和手写阶段提示适配的影响。
  插试管的后续阶段、倒球的放杯/回位阶段未在这些失败回合中触发，单元测试不能替代成功闭环验证。
- 插座每轮出现 2 条、球体每轮出现 14 条嵌套 RigidBodyAPI / xformstack 警告；两 checkpoint 一致，
  插试管没有这类警告。它们没有使回合中止或被计入 unstable，但物理保真度尚未独立验证。
  本轮保留原始资产；后续排查插入/倒球时需同时复核这些物理设置，不能把失败全部归因于模型。
- H100 训练未被修改或中断；未升级训练或仿真依赖。两个策略服务保留运行。
