# 35 类任务检查集

目标是用户提供的官方训练集对应的 **35 类，每类 3 条新生成、完整成功、三路 RGB episode**。最新实测结果、失败原因和视频入口由磁盘文件生成，见 [REVIEW.md](../../data/datagen_review35/REVIEW.md) 和 [status.json](../../data/datagen_review35/status.json)。程序实现、无图像 smoke、完整 RGB 采集、LeRobot 导出和恢复测试是独立状态，不能互相替代。

截至 2026-10-03 暂停整理时：**93 条有效成功 RGB，29 类各 3 条 LeRobot 已导出并读取验证，32 类至少一次完整物理成功**。其中 `display_letters` 使用重建定义；官方定义对应 28 类已导出、31 类完整物理通过。交换块seed10030完整1799帧直接RGB通过，该类三个不同seed共5156帧已导出，reader首/中/末帧9行验证通过。目标尚未全部完成。

**当前已暂停继续调试与新仿真启动。** 用户要求先整理能力边界，见 [35类能力表](CAPABILITIES.md)、[layout扩量指南](LAYOUT_GUIDE.md) 和 [暂停现场](PAUSED_STATE.md)。以下保留历史记录；其中的“已排队/正在运行/待验”是当时状态，不能代替最新结果。

直接打开 [视频与原子任务检查页](../../data/datagen_review35/review.html)，可选择任务、seed、subtask 和帧，播放完整三路视频并复制该帧的 Isaac 恢复命令。页面由检查进程持续更新，当前数量以页面和 `status.json` 为准。

```bash
bash scripts/datagen-uv.sh review --root data/datagen_review35 --export-ready
```

此命令递归检查 `raw` 的各采集分片，只接受 `complete=true`、`success=true`、RGB 帧数完整且存在 `terminal` 状态的文件。每条成功 RGB 轨迹都可先生成包含所有帧和三路相机的 `previews/<task>/*.mp4`；达到 3 条的任务导出到 `lerobot/<task>`，用真实 LeRobot reader 核对每条轨迹首、中、末帧。视频旁的 JSON 是半开区间 subtask 时间轴。超出官方动作预算的轨迹单独标记。

每类按 seed 去重；同一规划重复重放或渲染只计一条。`dispatch` / `campaign` 跨分片计数，`batch --reference-root <review-root>/raw` 还会跳过其他分片已成功的 seed。

`dispatch --follow --smoke-revision all` 持续关注尚未完成的任务：失败 smoke 不会永久跳过；新的成功版本出现后自动补采。相同 smoke 不反复消耗 GPU，每个新版本使用独立目录和有界 seed 预算；新版本的失败尝试不会覆盖旧文件。回归测试覆盖先失败、修复后采集、再次修复和凑齐数量后退出。

新任务先做物理 smoke，再决定是否启动 RGB 批量采集：

```bash
bash scripts/datagen-uv.sh campaign --tasks insert_key sweep_blocks \
  --root data/my_review --revision trial1 --episodes 3 --max-attempts 6
```

必须以 HDF5 的成功标志判断任务成功；Isaac Kit 的快速退出可能把进程退出码变为 0。`campaign`、`batch` 和 `review` 都检查实际文件。失败及中断文件保留；修改程序后用新的 `revision`，不会覆盖历史轨迹。

已成功的无图像规划可以在物理环境中重放并采集完整 RGB，减少重复规划：

```bash
bash scripts/datagen-uv.sh render_episode --input data/plan.h5 \
  --output data/rgb_episode.h5 --headless
```

此命令只恢复一次起始检查点，之后逐条执行原始动作并记录实际图像/状态；重新检查官方顺序奖励、最后 10 帧终态和对手执行状态，失败重放不进入检查集。它不会逐帧设置物体位姿或直接给无图像文件补成功标记。输出保存原规划哈希、实际执行源码归档和终态偏差报告。

`--mode state` 对已经通过物理验证的源轨迹逐帧恢复 checkpoint，再渲染三路图像。逐帧恢复误差必须小于 `1e-4`，并重新检查保存的末尾状态及任务历史。这种方式省去第二次物理推进；任务完成证据来自原始物理规划，而不是渲染阶段。输出以 `generation_mode=checkpoint_render_of_successful_physical_plan` 标识，保留原规划哈希及源码；不能将它作为一次独立物理重放成功的证据。

可持续将 `debug` 中新通过的物理规划渲染为检查 episode；仍按 seed 去重，任务达到数量后跳过：

```bash
bash scripts/datagen-uv.sh promote --root data/my_review --episodes 3 --follow
```

`--exclude-source` 可跳过由其他 worker 处理的规划。失败及中断渲染保留诊断文件，不作为成功 episode。

新启动的采集 worker 将无图像物理 smoke 排在 RGB 作业之前，仍使用同一把 GPU 排他锁，保留 CPU 导出并行。等待票据核对 PID 和进程启动时间，过期票据不会阻塞队列。旧版已排队 worker 正常完成，不做批量终止。

为防止连续 smoke 使 RGB 一直等待，队列增加 30 分钟等待保护：优先提升最早超时的 RGB 票据到 -2；没有此类 RGB 时才提升最早的普通票据到 -1。提升结果原子写回，让此前冻结源码的 worker 看到同一个执行次序。显式设置的负优先级诊断仍保留；仅调整等待作业，不终止或重启当前仿真。队列专项 4 项通过。

监督器的 `--timeout` 只计算获得 GPU 后的执行时间，等待 GPU 锁不消耗单条轨迹的运行预算。启动即报错仍会记录为进程失败。

当前容器 CPU 配额为 15 核。采集使用 8 个 Kit worker、4 个 Torch CPU 线程，单场景 cuRobo batch capacity 设为 1；动作仍是 25 Hz，每步 10 个物理 tick。后续导出使用 H.264 / CRF 20 / GOP 2，每相机 2 个编码线程，避免视频编码争抢仿真 CPU；之前已通过验证的 AV1 导出保留。

RGB 写入使用容量为 2 帧的后台 HDF5 队列；入队前复制所有可变数组和上下文，写入失败保留 partial 文件。单元测试覆盖缓冲区复用和后台异常，叠碗完整渲染已验证实际异步写入。逐帧 checkpoint 渲染仅首次进行材质预热，后续使用同步单帧采集，仍逐帧验证恢复误差。三相机合并 render-product 的实验在 Sim 5.1 annotator detach 时遇到无效图节点，未启用到采集流程。

后续原始 HDF5 图像改用无损 LZF，状态数组仍使用 gzip。三路 640×480 相机、连续 50 帧的离线对比为 gzip 写入 2.93 秒 / 82.35 MB，LZF 写入 1.78 秒 / 104.09 MB，两者读回与原图逐像素一致；见 [compression_benchmark.json](../../data/datagen_review35/compression_benchmark.json)。这是存储测试，不是整个 Isaac 采集的速度提升比例。

当前单张 GPU 上采集与恢复由 `.cache/datagen-isaac.lock` 串行化；CPU 导出可并行。此前两个 Isaac 实例并发出现 Vulkan device lost，不能用多个后台命令绕过该锁。新采集进程启动时冻结 Python 源码，包括等待 GPU 后才导入的模块；归档在 `.cache/datagen-source/<hash>.tar.gz`，episode metadata 包含 `source_snapshot` 和逐文件 SHA-256。早期 episode 尚无源码归档，仍保留原有源文件 hash。

## 定义和分布

35 类名单固定在 `src/datagen/tasks35.json`，不是扫描全部仓库任务类得到的数量。所有采集布局独立生成，不读取 `Eval_Layout`；当前采用明确受限的课程分布，并非官方随机布局分布的复刻。例如套娃只交换同一侧的一对、分类每类一个对象、早期充电器从竖直姿态开始（v93 起测试稳定平放初态）、传送带升高 6 cm 以避开桌面。训练用途和正式评测预算分别记录。

数据集中的拼写 RoboDojo 任务在本地及当前上游任务目录中都未找到对应类。`display_letters` 是依据数据集指令重建的临时任务，metadata 标为 `reconstructed_from_dataset_instruction`；导出不等于官方判据验证，检查表不会把它计作官方通过。

`organize_table` 存在指令文字差异：本地官方类及配置只有闹钟、手办、鼠标、键盘四个整理目标，所给训练集指令还包含开抽屉和收纳杂物。但抽查原数据集 episode 1800 的首、中、末帧也只有这四件物品，抽屉一直关闭，见 [对照画面](../../data/datagen_review35/reference_checks/official_episode_1800.jpg)。当前程序执行本地四目标定义，导出保留实际任务指令；不能据此宣称它完成了额外的开抽屉/收纳操作，也不能把单条抽查外推到原数据集全部样本。

推 T 当前采用沿柄方向推动的布局：物体与目标垫共同旋转 90°，使双指同时接触宽横梁；此课程避免横向推动凹轮廓时的非对称接触。v23 / seed 10001 的物理测试已通过：275 帧（官方预算 400 步），最终平面位置误差约 1.27 mm、相对朝向误差约 0.023°，完成松手、回零及末尾稳定检查；RGB 与其他种子仍以检查表为准。

塔楼 v30 已实际完成前七件的放置，并通过夹持平行端面提起三角屋顶；在搬运屋顶时，默认 5 cm 放置接近点仍无法通过 cuRobo 规划。v34 将屋顶接近余量显式设为 2 cm，随后完成全部八件、松爪、回零和末尾稳定检查，官方结构与朝向判据通过。共 2005 帧，超过 1050 步评测预算，因此属于训练示范，不是预算内评测成功；RGB 渲染及其他种子仍待完成。此前失败文件保留，不进入检查集。

倒球 v31 已完成 75° 倾斜、等待和放回杯子，机械臂全程完成，但七颗球全部未进入花瓶，官方检查失败。离线核对杯子的 USD 碰撞模型为凸分解，不能仅凭倾斜动作判断倒球成功。下一版本改为侧面抓持后增大倾角，必须重新通过七球入瓶及杯子直立检查。

木琴 v33 / seed 10001 的 622 帧物理轨迹通过官方八键顺序及终态检查，但超过 500 步评测预算。逐段核对标注目标时发现首键末尾槌头偏差约 18.24 mm，其余七键约 0.11–0.15 mm；因此不能把整任务通过解释成所有严格原子条件均通过。后续 v38 增加接触后槌头位置反馈校正，使用不同种子验证，结果以检查表为准。

装箱 v32 的小车入箱后，搬运鞋子时碰到侧面高箱盖，把箱子推移约 5 cm；随后锤子高位搬运规划失败。v36 改为按箱子实时位姿计算落点，经较低的前壁上方直线进入，尚待整任务验证。

丢瓶 v30 完成四次抓取和释放，但四瓶均未通过桶底判据。实际桌面宽 1.4 m，左边缘 X=-0.70；旧释放点 X=-0.51 仍在桌面上。v39 将桶移至 [-0.87, -0.40]，先经过未放物体的外侧通道，再倾斜持瓶，使瓶体到达桌外而手腕保持可达。此修正是独立训练布局和机器人运动调整，未修改原始资产或奖励；需要重新验证四瓶落入桶底。

交换积木 v29 的按钮初始控制器目标为约 2.90 mm，与 USD 作者设置的 6 mm 弹簧目标不一致；释放后它停在约 79% 行程，继续等待不会达到官方 90% 回弹阈值。该训练布局显式标记 `initialize_from_authored_drive_targets`，在初始静置前使用 [Isaac Sim 5.1 SingleArticulation.apply_action](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/py/source/extensions/isaacsim.core.prims/docs/index.html#isaacsim.core.prims.SingleArticulation.apply_action) 同步驱动目标，再由物理仿真自然回弹。未直接设置任务中的关节位置，也未修改回弹判据；标记保存在布局中供恢复时复用。v37 初始化实测发现 Torch 后端拒绝 NumPy `joint_indices`，已改为列表并同步修复 checkpoint 中控制器索引的恢复；v42 排队验证。

三连棋 v29 已通过全部四次对手落子稳定检查，但主方第五枚棋子搬运到远端中央格子时规划失败，因此整条不计成功。离线运动学检查表明，仅降低高度仍无法以竖直手腕到达该格；v41 对远端格采用 30° 前倾，预先检查落点及接近点的 cuRobo IK，再松爪让薄棋子自然落平，v41 已实际完整通过：1614 帧，四次对手稳定检查和最后十帧终态检查均通过；该示范超过官方 1100 步预算，RGB 待采集。对手动作没有跳过，也没有修改落点或交互判据。

叠碗当前限定深碗模型 1，并随机化位置。浅碗模型 9 的碗沿夹持在实测中出现倾斜、落碗带倒底碗，模型 10 尚未验证；它们不包含在当前检查集的资产覆盖声明中。

- 刚体的指定帧恢复及原动作续跑已实测；之前的堆叠/原子 lift 证据保留在 [VALIDATION.md](VALIDATION.md)。
- 外部关节物体保存 root、关节位置/速度/力和驱动目标。按按钮从第 70 帧（按下途中）恢复并续跑 56 步到释放阶段，恢复最大误差 `1.1920928955078125e-7`；结束时按钮关节行程比 `0.99937`。证据见 [press_restore.json](../../data/datagen_review35/press_restore.json)。该报告中的起始 `press` 原子条件在释放后为 false，是终点语义变化，不是恢复失败；整任务也尚未完成。
