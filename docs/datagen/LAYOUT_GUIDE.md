# 扩大 layout 与批量采集

先看 [35类能力表](CAPABILITIES.md) 选择任务。以下是恢复工作后的操作说明，**本文没有启动新的采集**；本次暂停的队列需先按 [暂停现场](PAUSED_STATE.md) 处理，否则旧的等待票据会阻塞新作业。

## 不改 planner，先扩大数量

当前可以直接改变 `seed`；它只改变现有 sampler 明确允许的资产、位置或排列。优先从 `stack_blocks`、`arrange_largest_number`、`classify_objects` 等已完成任务选取，先用固定源码采一个新的独立 seed 区间，估计产率，再扩大数量。

```bash
# 例：每类取得10条成功轨迹，每类最多尝试40个新seed。
# 这是运行示例，不是已经测得的10/40成功率。
bash scripts/datagen-uv.sh batch \
  --tasks stack_blocks arrange_largest_number classify_objects \
  --episodes 10 --max-attempts 40 --seed-start 20000 \
  --timeout 14400 --output data/layout_pilot_v1

bash scripts/datagen-uv.sh export \
  --input data/layout_pilot_v1 --output data/layout_pilot_v1_lerobot \
  --repo-id local/robodojo_layout_pilot_v1
```

`--episodes` 是每个任务在该批次目录中的成功目标数，包括已存在的成功轨迹；到达 `--max-attempts` 后可以少于目标。失败会保留，不进入成功导出。复用相同目录/相同 seed 区间可续跑；换 sampler、planner、资产或 seed 区间应使用新版本目录。

现有去重主要按 seed。**不同 seed 不保证不同 layout**：例如螺丝只从五组模型中有序选三组，位置固定，最多60个初始模型排列；四瓶从六种中有序选四种，固定位置下最多360个组合。100个离线 seed 中分别只出现49/90个不同布局。不能用重复渲染或换seed但布局相同来宣称新的几何覆盖；扩量统计应增加规范化 layout hash 和资产组合覆盖。

## 真正改变位置范围或布局结构

目前 `collect` **没有 `--layout`、`--layout-range` 或任意JSON布局注入参数**。它调用 `sample_layout(task, seed)`。需要在对应 sampler 中修改范围，并在必要时修改任务程序；文件对应关系见 [能力表代码入口](CAPABILITIES.md#代码入口)。不要把修改 `Eval_Layout` 当成训练采样入口：当前生成器不读取它。

建议一次只改变一类因素，并显式记录版本：

1. **同资产、小范围位置变化**：优先保持原方向、桌高和机器人。按现有毫米级扰动逐步扩大，不预先宣称新的厘米级区间均可达。
2. **成组移动工装**：硬币与支架、面包与架子、槌与槌架、电脑与支架、瓶与初始液体必须保留物理支撑关系。`jitter_groups` 只做 XY共同平移；它不会旋转整组，也不会自动变换 planner 中的世界坐标 waypoint。
3. **姿态变化**：需要同时检查夹爪方向、抓点、抬升/搬运/插入/撤手、持物包围体和IK分支。杯把、钥匙孔、箱盖、蛋盒盖、试管架等对方向敏感，不能只随机一个 quaternion。
4. **资产/尺寸/数量变化**：检查 label 和任务循环是否仍成立、metadata功能点是否存在、夹爪开度能否包围、重心与摩擦是否改变抓持。`for i in range(3)` 等固定流程不会自动支持多一件。
5. **动态与交互场景**：棋盘/麻将涉及发布的支持臂轨迹；整体平移主场景不会同步对手。传送带当前固定速度和前馈量。布料/液体变化还会改变接触和粒子动力学，应单独建验证版本。

以下改动不属于当前“换 layout 即批采”的范围：机器人安装位姿、桌面高度/尺寸、随机clutter、任意目标模型、物理摩擦/质量、摄像机/灯光大范围随机化。它们可以作为后续开发方向，但现有3条检查集不提供相应泛化证据。

## 每个新布局版本的验证顺序

先做初始支撑/重叠检查和全段可达性筛查，再运行真实物理。端点可达不代表夹取、带物体搬运、释放和回零都可达；不要只检查最终目标。

```bash
# 新版本的单个完整初态物理测试，不记录RGB。
bash scripts/datagen-uv.sh collect --task stack_blocks --seed 20000 \
  --no-images --headless --output data/layout_v2/smoke_seed20000.h5
```

检查实际 HDF5 的 `complete/success/reason`、终态与日志。不能只看进程退出码，也不能把恢复后缀的 `program_completed=true` 当成完整成功。旧源码冻结的等待 worker 不会使用刚改的程序；新版本必须由新worker采集。

新分布适合用两组互不重复的 seed：调参组用于修复，保留组用于测成功率。推荐先检查20–50个保留seed作为工程试验规模，**这只是建议的测量数量，并非目前已完成的验证**。报表至少包含：

- 完整物理成功数／实际物理尝试数；启动/存储故障单列，禁止混成planner失败。
- 独立layout hash数、位置/朝向范围、成功资产组合及各自分母。
- 每条帧数、耗时、官方动作预算内比例，失败发生的subtask。
- 抓空、滑移、关节限位、非预期碰撞、终态不稳等原因，以及首/关键/末帧视觉检查。

固定一个版本后再生成完整RGB和LeRobot。已有成功无图像规划可通过物理重放或checkpoint渲染补图，但应保留模式标签与原seed；精细接触任务的物理重放可能再次失败，不能直接补一个成功标志。

## 给训练数据增加变化时的优先级

先增加**已验证资产上的几何变化**，再增加语义组合和外观变化；只有静态背景/纹理变化，不能补足抓点、路径、目标位姿的覆盖。当前采样器会随机部分纹理/牌面/数字，尚无统一相机、灯光、背景随机化开关。

建议第一轮按现有能力表的12类“优先批采”测产率，其中数量/排列变化仍受各自任务限制；16类“窄范围批采”保持工具、工装和接触参数。蛋盒、折衣、整理桌面先解决不稳定环节；倒液、电脑、扫块先取得完整初态成功，再讨论扩分布。

`display_letters` 应保留为单独标记的重建任务。`general_pickup`、`stack_blocks_by_language` 虽有辅助采集入口，但不在此次35类清单内；其他 `*_random` 官方类也不会因为基础任务已有程序而自动得到支持。

## 原子任务采样

完整成功episode可用 `export --split-subtasks` 导出原子片段，保存来源帧和状态sidecar；无需重新构造一个脱离实际前置条件的场景。planner自动提供阶段、对象、手臂和目标字段；LLM/VLM可经annotation hook补充语义。

扩量时应按原语、对象、起始高度、已抓持/未抓持、左右手、遮挡和前置任务状态分层统计。只在某个成功检查点反复恢复相同原动作，会增加帧数，但几乎不增加前置状态分布。若用VLA在中途继续测试，应同时报告恢复误差、原子成功、整任务成功和是否提供历史观察，避免将它们合并成一个分数。
