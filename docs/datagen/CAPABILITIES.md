# 当前 planner 能力与 layout 扩展范围

更新：2026-10-03。这是当前实现和检查集的能力说明，不是对任意场景的成功率承诺。入口见 [操作说明](README.md)，逐条视频见 [检查页](../../data/datagen_review35/review.html)，失败与修复证据见 [历史记录](REVIEW35.md)。

## 当前可用程度

- 已有 **93 条完整成功、三路 RGB 的新轨迹**；**29 类各 3 条已导出 LeRobot v3，并用真实 reader 读回验证**。其余三类各 2 条、三类 0 条。
- `display_letters` 是依据数据集指令重建的任务。因此上述结果中，**官方定义对应 28 类三条导出**；已有至少一次完整物理成功的 32 类中，官方定义为 31 类。
- 这些成功样例跨多个源码版本。它们证明对应布局、资产和版本的执行成功，**不构成当前代码在全部 seed、全部模型或官方随机分布上的回归通过**。
- 用户已要求暂时收束。等待中的 GPU 作业和自动调度已暂停；当时正在运行的折衣 seed10018自然结束，1232 帧后左衣摆抬升失败，没有新增成功样例。见 [暂停现场](PAUSED_STATE.md)。

当前适合的批量方案是：**在已经约束好的课程布局里生成新 seed，执行真实物理，过滤成功，再导出**。扩大布局范围需要重新验证。直接把物体放到任意位置、替换任意资产、改变物体数量或移动整套机器人，不是当前 planner 已支持的能力。

## 35 类具体范围

表中的范围是**当前 sampler 已实现的随机化**，不是统计得到的连续可成功区域。单位为世界坐标，`±` 表示当前配置的扰动上限；模型编号来自本仓库资产。底层机器人、桌面、相机和物理参数保持当前配置。

建议列：**优先批采**＝先在现有范围做独立成功率测试；**窄范围批采**＝保持固定工装/抓法，仅使用表中已有变化；**暂缓扩量**＝还不适合作为稳定整任务批量来源；**重建任务**＝可作额外训练，不能记作官方定义验证。所有类别仍需逐条成功过滤。

当前 sampler 的100个 seed 离线展开、已成功 episode 的实际资产及源码信息，保存于 [layout_capability_audit_oct3.json](../../data/datagen_review35/reference_checks/layout_capability_audit_oct3.json)。这是代码/元数据审计，**不是3500条仿真测试**；采样器允许的模型集与已成功样例实际覆盖的模型集分别记录。

成功样例实际资产覆盖也较小：方块当前成功覆盖采样器三种尺寸中的两种；套娃三套纹理中的两套；螺丝五组模型中的四组；布料只成功过Top_Long/4、9，未证明model1可用。其余已配置但未成功的资产不能直接记作已验证覆盖。

93条中32条标记为官方预算内、57条超预算、4条不适用或未知。生成来源为53条直接采集、3条物理重放、37条checkpoint补图；完整来源与预算边界见[暂停现场](PAUSED_STATE.md)。

## Planner 实际使用的信息和控制

这是基于仿真真值的任务专家：读取对象 label、资产 metadata、实际 pose、功能点、关节/粒子状态以及任务内部顺序，调用真实 cuRobo v2 和物理执行。数字/类别/目标物选择不经过视觉模型；生成的 RGB 可用于训练 VLA，但不能用专家成功证明 VLA 的视觉识别、语言理解或记忆能力。

- **运动规划**：普通搬运与归位使用 cuRobo 的位姿/关节路径规划；接触接近和精细操作使用笛卡尔插值与连续 IK。拒绝超过0.35 rad的相邻关节跳变。不是所有路径都能由另一分支或另一手臂自动接管。
- **抓取生成**：包围盒、功能点、预设方向候选和已调试的资产专用抓点；部分任务按实际抓持偏移重新计算放置。没有通用 grasp network、任意网格的力闭合搜索或滑落后自主重新抓取。
- **反馈**：有抬升、目标位姿、工具功能点、夹持偏移、行程、内容物入容器等实际检查。反馈通常局限于当前原语；失败时停止该 episode，换 seed 重试，不进行通用任务级重规划。
- **双臂**：通常顺序操作，通过桌面缓冲或专门交接完成跨臂搬运。布料等使用特定双臂控制；没有通用14自由度联合碰撞规划。
- **物理**：不通过设置物体/粒子完成任务，不放宽原奖励。训练布局和明确记录的适配可以与官方默认初态不同；这些差异保存在 metadata，不能隐藏成原官方随机分布。

## 碰撞、场景变化和成功过滤的限制

cuRobo 世界默认只有机器人自身球模型和桌面 cuboid；显式调用 `include_static_geometry` 才把指定物体的当前网格 AABB 加入三套规划世界。它不自动更新全部场景、不附着手中物体、不覆盖另一只手臂。手指 link7/link8 未完整包含在原球模型；实测还发生过球模型漏掉 link3/link5 接触。

另外，原规划桌面顶面约世界 Z=0.740 m，实际桌面为0.765 m，存在25 mm差异。当前任务通过固定布局、抬手/撤手路线及针对性几何/接触诊断避免已知问题。**IK可达、球间隙为正、末态成功，均不能单独证明全程无非预期碰撞。** PhysX接触否决目前只在部分敏感流程/诊断启用，没有统一覆盖全部93条历史轨迹。

因此新增 clutter、改桌高、改相机支架、改变物体尺寸/摩擦、整体平移或旋转工装，需要重新检查手指、持物、双臂和全过程运动。不能只用初始物体之间不重叠来判断可采集。

当前批处理按任务成功筛选；新版本还重查原终态最后10帧稳定窗口及对手状态。早期冻结 worker 的检查能力不同，见各自 metadata/报告。成功集来自多个版本的有目的调试，失败数也混合了启动问题和物理失败，**不应把累计成功/累计文件数当作某个固定 planner 的成功率**。需要在固定源码、固定分布的新 seed 上另测。

## 与打榜、原子任务及恢复的关系

- 大量轨迹超过官方 `step_lim`，仍可作为明确标记的训练示范。使用 `within_benchmark_budget` 区分；字段缺失表示未知，不能当作预算内。整任务完成不等于打榜预算内成功，更不等于训练后模型的分数。
- 三路图像可能来自直接物理采集、原动作物理重放，或成功物理轨迹的逐帧 checkpoint 渲染。后者可作为原示范配图，但不是独立新轨迹；按 seed 去重，保留 `generation_mode` 和源哈希。
- 自动 subtask 是 planner 阶段标注，不是 VLM 对真实接触时刻的精确识别。可用 `--split-subtasks` 切片；闭爪阶段不能单独证明抓稳，部分原子指标会返回 `null`。旧数据没有记录的目标字段不自动补齐。
- 新生成数据可按帧、时间或 subtask 恢复，接14维绝对关节动作 VLA。机器人、外部刚体、关节、任务历史和控制器目标均需恢复；原官方 LeRobot 数据不含这些检查点，不能直接精确还原。
- 刚体和若干关节/交互中途恢复已实测。布料必须使用动态变换完整的 v2状态：一次夹持恢复世界误差0，20步续跑最大约2.81 mm，但不是所有折叠阶段验证。流体即时恢复可很小，10步后粒子差曾达约5.8 cm；未保存接触/粒子求解器内部缓存，不能承诺确定性续跑。
- 原子 VLA 从中途恢复且清空模型历史，测的是给定物理前置条件下的能力，不能替代整任务中的感知/记忆测试。尚未接入用户模型测得 VLA 分数。
